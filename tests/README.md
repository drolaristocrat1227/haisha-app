# テストについて

配車アプリの動作を自動で確認するためのテストです。
アプリ本体（`index.html`）に手を入れたあと、**壊れていないかを一発で確かめる**ために使います。

## 実行のしかた

初回だけ、テストに必要なものを入れます。

```
npm install
```

あとは毎回これだけです。

```
npm test
```

すべて通れば最後に `✓ ○○ 件すべて成功` と出ます。
失敗した項目は `✗` と理由が表示されるので、そこを直してからもう一度実行してください。

## 仕組み

- `harness.js` … 本物の `index.html` を jsdom（Node.js上の仮想ブラウザ）で開き、
  アプリ内の関数を呼べるようにするための下準備。**アプリ側にテスト用のコードは足していません。**
- `fixtures.js` … テストで使う架空のチーム構成（スタッフ2名・3年父兄6名・2年父兄4名など）。
- `runner.js` … 小さなテスト実行係。外部のテストツールは使っていません。
- `run-tests.js` … テスト本体。ここに検証したい項目を書きます。

## 何を守っているか

| 分類 | 内容 |
| --- | --- |
| 自動配車：基本 | 全員が配置される／運転手のいない車を作らない／二重配置しない／乗車人数のルール／運転手不足の受け皿 |
| 自動配車：手動配置 | 手動で置いた人が消えない・重複しない／2回実行しても壊れない |
| 自動配車：マネージャー | チームトラック優先、無ければ軽トラの助手席へ |
| 参加者選択 | 乗車済みの人のロック／一括操作でも外れない |
| タップ操作 | 配置・移動・入れ替え・取り消し・定員チェック |
| 車の並び替え | 上下ボタンでの入れ替え／再描画で戻らない |
| データの保存・復元 | 書き出し内容／復元／不正なデータを弾く |
| テキスト出力 | 選手号の学年別人数が出る |
| スマホでの使い勝手 | 拡大禁止にしない／入力欄16px以上／タップ領域44px以上／スクロールを妨げない |

## テストを足したいとき

`run-tests.js` に、同じ書き方で追加してください。

```js
describe('まとまりの名前', () => {
  it('こうなってほしい、という説明', () => {
    const api = boot({ settings: F.settings(), session: F.session({ attending: F.ALL_ADULTS }) });
    api.runAutoAssign();
    eq(api.SS.vehicles.length, 2, 'ここが違ったときに出るメッセージ');
  });
});
```

- `eq(実際, 期待, メッセージ)` … 値が一致するか
- `check(条件, メッセージ)` … 条件を満たすか
- `api.dump()` … 各車の乗車状況を文字にして返す（失敗の原因を見るときに便利）

アプリ内の関数を新しく呼びたくなったら、`harness.js` の `EXPOSED` にその名前を足してください。
